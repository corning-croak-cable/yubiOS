# yubiOS Specification

Version 0.3 - 2026-07-11 - Status: pre-launch, tracks `main`

This document defines the normative surface for yubiOS. Architecture rationale lives in [ARCHITECTURE.md](ARCHITECTURE.md), accepted decisions live in [ADR.md](ADR.md), threat coverage lives in [MITIGATE.md](MITIGATE.md), and pinned inputs live in [PINNED.md](PINNED.md).

The key words MUST, MUST NOT, SHOULD, and MAY are to be interpreted as described in RFC 2119.

## 1. Scope

yubiOS is a FIDO2-first immutable Linux operating system in which the owner-held YubiKey 5 series token is the mandatory human-presence and identity root. It replaces TPM-centered owner workflows at the boundaries the owner touches: Secure Boot signing, disk unlock, home unlock, SSH, and PAM login.

ARM64 is the primary platform because it is the only current target where yubiOS can plausibly own the root of trust below the UKI through TF-A, OP-TEE, fTPM, and U-Boot. x86-64 remains fully supported but secondary because its firmware and TPM roots are OEM-supplied.

Out of scope: application-level security, hardware below an unowned firmware boundary, replacing OEM x86-64 firmware, and non-YubiKey FIDO2 tokens unless explicitly validated.

## 2. Design Principles

1. Owner-held trust anchors MUST gate owner actions. Mandatory key material MUST be generated by and controlled by the owner.
2. Every boot component from bootloader to userspace MUST be signed, measured, or hash-verified before use.
3. `/usr` MUST be immutable and verified through composefs, erofs, and dm-verity.
4. OS updates MUST NOT require disk-unlock re-enrollment. LUKS2 enrollments use FIDO2 hmac-secret rather than TPM PCR-hash policies.
5. Physical presence MUST be required for unlock and privileged identity actions.
6. Build inputs MUST be digest-pinned in [PINNED.md](PINNED.md), and policy gates MUST reject mutable base references.
7. Security exceptions MUST be narrow, documented, and scoped to the service that needs them.

## 3. Trust Model

| Root | Hardware | Question answered | Scope |
|---|---|---|---|
| YubiKey 5 | Owner-held external token | Is the authorized owner present? | PIV signing, FIDO2 unlocks, SSH, PAM/U2F, OATH/TOTP |
| TPM/fTPM | Platform device or yubiOS-owned ARM64 secure-world TA | Did this platform boot the expected measured stack? | PCR measurement, attestation, `ConditionSecurity=measured-os` |

The TPM/fTPM MUST NOT become the sole disk-unlock gate. It may provide measurement and attestation, while the YubiKey remains the owner-held secret-release mechanism.

## 4. Interface Requirements

| Boundary | Required interface | Required behavior |
|---|---|---|
| UKI / Secure Boot signing | YubiKey PIV slot 9c over CCID/PKCS#11 | `systemd-sbsign` signs artifacts with owner-controlled key material |
| Root and swap unlock | FIDO2 hmac-secret over hidraw | `systemd-cryptenroll --fido2-device=auto --fido2-with-client-pin=yes` plus offline recovery key |
| User homes | systemd-homed LUKS2 + FIDO2 | Per-user home unlock requires the user's FIDO2 credential |
| SSH | OpenSSH `ed25519-sk` resident credentials | Administrative keys SHOULD require verification/PIN |
| Login/sudo | pam-u2f >= 1.3.1 | PAM entries MUST be `required`, not silently bypassable |

## 5. Boot Requirements

### ARM64 primary path

Path A boards MUST use owner-provisioned ROTPK/fuse state before they are described as production Path A. TF-A, OP-TEE, StandaloneMM, fTPM, U-Boot UEFI, systemd-boot, and the UKI MUST chain through owner-controlled or pinned inputs. Path B boards MAY be used for development and measured/attested deployments, but documentation MUST clearly say they are not boot-time rejection equivalents.

### x86-64 supported path

x86-64 MUST support the same signed UKI, FIDO2 unlock, immutable `/usr`, and update model. Documentation MUST state that firmware and TPM roots remain OEM-supplied unless future work changes that scope.

## 6. Runtime Filesystem Requirements

- The deployed OS image MUST treat `/usr` as read-only and verified.
- Writable state MUST live outside `/usr` and be created on target hardware.
- No shipped system should require a traditional `/etc/fstab` for discoverable partitions.
- First-boot partition creation SHOULD use systemd-repart and DPS labels.

## 7. Update Requirements

- Bootc/OCI and mkosi outputs MUST remain behaviorally aligned for the base runtime.
- Production OCI tags MUST NOT include TEST-only software FIDO2 authenticators such as `passless`.
- `dev`/`dev-<sha>` tags MAY include swu2f tooling only with explicit TEST-only labels and CI assertions.
- Published artifacts SHOULD include provenance, SBOM, and digest-addressable references.

## 8. Hardening Baseline

Services SHOULD use systemd sandboxing appropriate to their role, including `ProtectSystem=`, `PrivateDevices=`, `RestrictNamespaces=`, capability bounding, and network isolation.

The 2026-07-11 research cycle corrected a prior wording issue: `RestrictFileSystems=` is the existing BPF-LSM filesystem-type limiter documented by `systemd.exec(5)` and must not be described as a new systemd v261 feature. systemd v261 introduced `RestrictFileSystemAccess=`, which remains a separate future audit item.

## 9. Cryptographic And TLS Requirements

- OpenSSL clients in the image MUST remain at OpenSSL 3.5+ or equivalent for default `X25519MLKEM768` hybrid TLS support.
- Go-based registry/update clients SHOULD remain on Go 1.24+ so the Go TLS default includes `X25519MLKEM768` when curve preferences are unset.
- yubiOS code MUST NOT pin TLS curves away from upstream hybrid defaults without an ADR.

## 10. Validation Requirements

| Area | Required evidence |
|---|---|
| Base image | Current digest and package/tool floor in [PINNED.md](PINNED.md) |
| UKI signing | `systemd-sbsign` or CI SoftHSM equivalent plus `sbverify` assertion |
| LUKS2/FIDO2 | Real or swu2f-backed boot test, clearly labeled by trust level |
| ARM64 secure world | QEMU and then real-board evidence before production claims |
| PQ TLS | CI or documented live handshake evidence showing ML-KEM hybrid negotiation |
| zstd EFI zboot | Pinned QEMU workaround or upstream fixed QEMU version, not an assumed default |
