## Honest caveats

1. **Edits are heuristic** -- each per-primitive edit is a templated section, not a deep read of the file. A more sophisticated new-idea generator would read each file and propose file-specific content (LLM-as-judge, or AST-aware analysis).
2. **Coverage not re-measured in this PR** -- the delta is the predicted primitive flip; a re-binarization would verify.
3. **Order matters** -- new-ideas are appended at the end of the file, not inserted at the top. Section ordering follows what compile-time was at EOF, not what is most semantic.

## New-idea format (v1.1.0)

Each new-idea is a CONCRETE EXPERIMENT with:

- **lens**: ID (L539 onwards)
- **file**: path relative to repo root
- **primitive_added**: which primitive the new-idea closes
- **hypothesis**: a testable claim about closing that primitive
- **method**: how the test runs (heuristic section append)
- **parameters**: `{basis, d, seed, primitive, context_chars}`
- **delta**: `{k_before, k_after, primitive_added, lines_added}`
- **verdict**: YES (edit applied) / NO (couldn't generate)
- **score**: 0-50 rank
- **caveat**: heuristic, not deep-read

The new-idea is the EDIT, not prose about the file. Each new-idea's edit content lives in the file; the JSON in `lenses.json` records the experiment metadata.
