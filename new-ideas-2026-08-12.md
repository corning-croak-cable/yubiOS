## Honest caveats

1. **NSS sweep is heuristic regex-based** -- the 12-axis gap-finding uses pattern matching, not deep semantic analysis. LLM-as-judge would refine.
2. **Priority order is opinionated** -- per the NSS SKILL.md, the axis priority reflects 'what's most impactful to add to a file'. Calibration (verification) is first because it's most actionable; Recursion (anti-patterns) is last because it's least.
3. **File-type detection is heuristic** -- conf files (incl. modprobe.d, tmpfiles.d, dracut.conf.d, udev/rules.d, pam.d, systemd) use single-# comments; markdown uses ## sections. The cycle-5 fix is preserved.
4. **PR #206's per-file patches already addressed the highest-priority missing primitive** -- cycle 7's NSS-informed approach may address a DIFFERENT gap (the cycle-6 primitive, plus a different NSS axis). Some files may see minimal change.

## Cycle 8 -- RSI NSS-audience deep research (2026-08-12)

**NSS axis:** `audience` (first of the 12 NSS axes; the others are
Inputs, Outputs, Mode, Assumption set, Adjacent problems, Failure modes,
Lifecycle, Composition, Knowledge sources, Calibration, Recursion --
covered in cycle 7).

**Deep research synthesis:** Audience is not a folder axis and not a
single persona label. It is a coverage relation -- reader cell x job x
context x required form -> findable, complete, current path. The
synthesis draws on Google Technical Writing (role + proximity + required
knowledge), DITA audience/experience/job profiling (machine-readable
metadata + conditional processing), Diataxis (mode as a separate axis
from audience), Doc Detective persona-driven strategy (primary persona
+ Critical User Journey + outcome-first organization), GitBook persona
+ Jobs-to-Be-Done pattern, Temporal 2021 docs-info-arch redesign
(per-persona landing pages over shared reference shelf), Ductile
audience matrix (human/agent x coder/operator x learner/expert ->
8-cell coverage), and docs-as-code frontmatter enforcement (Docusaurus,
GitHub Docs YAML, Structured MADR `audience` field).
