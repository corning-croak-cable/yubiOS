## Honest caveats

1. **One primitive per file is a hard constraint** -- a file missing 5 primitives still gets only 1 flip per cycle. Multiple cycles converge over time.
2. **Priority order is opinionated** -- the cycle-0 single-action pattern started with `has_priority`; cycle 6 uses purpose > verification > examples > ... > changelog (most foundational first, history last).
3. **File-type detection is heuristic** -- the `conf` class includes `.conf`, `.rules`, `.preset`, `.toml`, `.cfg`, and paths under modprobe.d, tmpfiles.d, dracut.conf.d, udev/rules.d, pam.d, systemd. A stricter detector would inspect the actual first-line syntax.
4. **Edit content is still heuristic** -- the patches derive from the file's basename + first lines but do not deeply read the file. LLM-as-judge would refine.
